## 本轮上线总控摘要

本轮重点验证：

- 手机端首页、发现页、详情页不应横向溢出。
- 手机端顶部菜单、登录按钮、侧栏抽屉和登录弹窗不应遮挡或超出屏幕。
- 首页滚动后，底部紧凑发布条应正常出现，按钮和文案不应挤出屏幕。
- 点击紧凑发布条后，应能回到首页发布框。
- 投稿未读/已读计数不应因为刷新任务列表而丢失。
- 发现/市场动态只展示可公开任务，过滤测试任务、测试支付、关闭任务。
- 不主动触发真实付款、采用投稿、结算、退款、短信。

## 本轮主要变更

1. 手机端布局稳定
- 页面整体限制横向溢出。
- 手机端顶部菜单和登录按钮使用安全区偏移，避免贴边或被刘海遮挡。
- 手机端侧栏改为屏幕内抽屉卡片，宽度不超过视口。
- 登录弹窗在手机端可滚动，输入框和按钮字号提升到 16px，减少 iOS 自动放大。
- 详情页附件行在手机端保持横向结构，操作按钮固定在右侧。

2. 首页紧凑发布条
- 底部紧凑发布条的输入区改为按钮式展示，避免只读 textarea 带来的光标、键盘和高度问题。
- 滚动监听改为基于页面位置判断，兼容 `.studio-content` 内部滚动。
- 手机端点击紧凑发布条后回到顶部发布框，减少横向滚动干扰。

3. 投稿已读计数
- 本地已读计数会和最新任务列表对齐。
- 已存在的已读记录会保留，新任务会初始化计数。
- 目标是减少投稿红点/未读数量在刷新后的异常变化。

4. 发现/市场过滤
- 公开市场只统计和展示 `ACTIVE`、`PENDING_SELECTION`、`COMPLETED` 状态任务。
- 过滤包含“测试支付”“支付流程”“不用接单”等测试描述。
- `CLOSED` 状态展示文案从“已完成”改为“已结束”，避免误导为正常完成订单。

5. 开发与渲染兼容
- 根节点增加 `suppressHydrationWarning`，减少浏览器扩展或环境差异带来的 hydration 警告。
- `next.config.ts` 增加局域网开发来源 `192.168.31.16`，用于本地手机预览；不包含密钥。

## 本轮重点测试路径

- `npm run build` 必须通过。
- `npm run lint` 建议执行，允许既有 warning，但不能有 error。
- `git diff --check` 必须通过。
- 桌面打开首页，确认市场预览和紧凑发布条正常。
- 手机视口打开首页，确认无横向溢出，顶部菜单和登录按钮在屏幕内。
- 手机视口滚动首页，确认底部紧凑发布条出现且不超出屏幕。
- 手机视口打开 `/market`，确认市场预览不横向溢出。
- 检查浏览器控制台不能有运行时 error。
- 抽查市场接口或页面，确认测试任务/关闭任务不会进入公开市场展示。

## 本轮高风险点

- 这是手机端布局和滚动行为改动，真实手机仍建议上线后继续观察。
- 紧凑发布条从 textarea 改成按钮式展示，需观察用户点击后是否能顺畅回到发布框。
- 投稿已读计数会影响红点/未读提示，需观察新投稿到来后的提示是否准确。
- 市场过滤会让公开市场数量减少，这是预期结果，不是数据丢失。
- 本轮不验证真实付款、采用投稿、结算、退款。
