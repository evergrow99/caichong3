# AICHONG 待验证清单

更新时间：2026-05-28
用途：集中记录哪些地方还没验证，尤其是钱、短信、权限、结算和生产配置。

## 使用方式

- 每次上线前，上线总控应读取本清单。
- 每次测试线程发现已验证或未验证事项，应更新本清单或在测试结论中明确说明。
- 高风险项没有验证，不代表一定不能继续开发，但不能把它说成“已安全”。

## 验证等级

- P0：必须先确认，不能含糊。通常涉及钱、结算、权限、生产配置、真实用户数据。
- P1：上线前应验证。通常涉及核心路径、短信、同步、附件、后台。
- P2：可带观察。通常涉及局部体验、文案、非核心展示。

## P0 高风险待验证

| 项目 | 当前状态 | 为什么重要 | 下一步 |
|---|---|---|---|
| 真实采用投稿并触发才虫结算 | 待主人单独确认后验证 | 会影响真实订单结果和资金结算 | 先确认是否允许使用真实 1 元测试单 |
| 用户只能看到自己的订单和投稿 | 已有规则，仍需持续回归 | 一旦出错就是隐私和权限事故 | 每次改订单、投稿、附件接口都要测 |
| 管理员权限只允许 `ADMIN_PHONES` | 已有规则，仍需上线前复核 | 管理后台可见敏感运营数据 | 上线前检查生产 `ADMIN_PHONES` |
| 生产环境不得开启开发登录 | 待每次上线前确认 | 开发登录进入生产会造成安全风险 | 检查 `ALLOW_DEV_LOGIN` |
| 生产环境不得使用模拟才虫 | 待每次上线前确认 | 模拟模式会导致真实业务不可用 | 检查 `CAICHONG_USE_MOCK` |
| 生产密钥只在服务端使用 | 待每次上线前确认 | 密钥泄露会影响数据库、短信、才虫账号 | 检查构建和环境变量用法 |

## P1 核心链路待验证

| 项目 | 当前状态 | 为什么重要 | 下一步 |
|---|---|---|---|
| 真实支付后状态同步 | 已有链路，需要持续观察 | 用户付款后必须看到任务进入提交期 | 用测试单观察支付后订单状态 |
| 投稿同步及时性 | 已有心跳和兜底策略 | 投稿不同步会影响用户查看和短信提醒 | 检查 heartbeat 日志和订单详情 |
| 新投稿短信提醒 | 已接入，真实发送需谨慎 | 用户依赖提醒，但误发会打扰和产生成本 | 只在主人确认后做真实短信测试 |
| 进入选择期短信提醒 | 已接入，需生产观察 | 影响用户及时选择投稿 | 检查模板、日志和幂等记录 |
| 选择截止前提醒 | 已接入，需生产观察 | 影响超时未选择风险 | 检查时间计算和重复发送 |
| 附件下载和预览 | 已做部分验证 | 影响用户查看投稿结果 | 用真实含附件投稿订单手工回归 |
| 后台健康检查 | 已有页面 | 是运营排查入口 | 上线前打开后台确认 |
| 外部 5 分钟 Cron | 文档建议，需配置确认 | 影响提醒及时性 | 确认 cron-job.org 或等价服务运行 |

## P2 可观察项

| 项目 | 当前状态 | 为什么重要 | 下一步 |
|---|---|---|---|
| 首页市场动态展示 | 已接入 | 影响真实感和信任感 | 观察是否混入测试任务 |
| 订单状态文案 | 可继续优化 | 影响普通用户理解 | 后续体验优化时处理 |
| 后台日志可读说明 | 可继续优化 | 影响排查效率 | 后续后台线程处理 |
| 空状态和错误提示 | 可继续优化 | 影响用户信心 | 后续前台体验线程处理 |

## Harness 第一阶段应覆盖

第一阶段只做安全检查，不自动触发真实付款、真实短信或真实结算。

- 网站是否能打开。
- `/api/health/readiness` 是否 ready。
- Supabase 是否连接正常。
- 才虫 API 配置是否存在并可安全检查。
- 关键生产环境变量是否缺失。
- 生产环境是否误开开发登录。
- 生产环境是否误开模拟模式。
- 后台管理员权限是否配置。
- 订单接口是否有用户归属校验。
- 投稿和附件接口是否有用户归属校验。
- 短信配置是否完整，但不真实发送。
- 最近 operation logs 是否有高风险错误。
- 本轮改动是否触碰钱、短信、权限、订单、投稿、附件、数据库、环境变量。

## 每次上线前最短检查

```text
1. 本轮到底改了什么？
2. 是否涉及钱、短信、权限、订单、投稿、附件、数据库、生产配置？
3. 构建是否通过？
4. 测试线程是否给出结论？
5. 上线总控是否明确说“可上线”？
6. 是否有未验证的 P0 风险？
```
