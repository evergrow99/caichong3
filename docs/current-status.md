# AICHONG 当前状态

更新时间：2026-05-28
用途：给新线程快速了解项目现在做到哪一步，哪些已经完成，哪些还没完成。

## 一句话状态

AICHONG 已经不是页面 Demo，而是进入真实 MVP 试运营前后阶段的产品。核心发单、登录、订单、投稿、后台、同步和短信提醒链路已经具备雏形，但真实付款、采用投稿、结算、权限、短信和生产配置仍然是最高风险区。

## 已经完成

- 真实才虫 API Key 已接入，当前项目不是单纯模拟模式。
- Supabase 已接入，可保存用户、订单、附件、投稿、操作日志。
- 手机号登录已接入；本地开发环境支持开发验证码。
- 普通用户订单和管理员后台已做登录隔离，前台账号和后台账号不应互相覆盖。
- 发单流程已具备：需求、价格、附件、创建任务、支付链接。
- 附件规则已具备：最多 5 个，单个最大 10MB，支持部分文件预览和下载。
- 订单和投稿可从才虫同步到 AICHONG 自己的数据库。
- 心跳同步支持用户手动触发和平台定时触发。
- 订单短信提醒链路已接入，包括新投稿、进入选择期、选择截止前提醒，并有防重复记录。
- 后台 `/admin` 已具备管理员登录、健康检查、订单概览、短信提醒记录和最近日志。
- 首页已接入市场动态预览，包括发单统计、任务用例、分类筛选和需求详情抽屉。
- 旧测试单已从真实运营统计中排除。
- 上线协作文档、测试摘要文档、协作宪法红线版已开始建立。

## 已经验证过的关键路径

- 本地构建、lint 和部分接口验证在最近上线轮次中通过。
- 前后台登录隔离已做本地验证。
- 后台管理员登录、退出和前台普通用户登录互不覆盖已做验证。
- 投稿附件下载代理的响应头和安全边界已做接口验证。
- 短信提醒链路已具备幂等记录和后台展示，但真实发送仍应谨慎确认。

## 未完成或需要继续完善

- 真实采用投稿后的完整闭环仍需单独确认后验证，因为会触发真实结算风险。
- 生产环境短信模板、阿里云模板 Code 和实际发送效果仍需持续确认。
- 生产环境变量和外部调度配置需要上线前逐项核对。
- 后台还可以继续完善订单详情入口、状态筛选、异常日志说明和“需要处理”的订单提示。
- 普通用户体验还可以继续优化订单状态文案、支付后提示、等待投稿提示、选择投稿提示和空状态。
- Harness 还没有做成后台功能，目前只确认了第一阶段原则：只做安全检查，不自动触发真实付款、真实短信、真实结算。

## 主人需要亲自确认的事情

- 是否允许对真实 1 元测试单执行采用投稿，进而触发才虫结算。
- 生产环境短信服务模板和模板 Code 是否最终可用。
- 正式域名、站点名称、Logo 和基础文案是否最终确定。
- 上线前 Vercel、Supabase、阿里云、才虫、Cron 等生产配置是否可以操作。

## 继续推进的建议顺序

1. 先稳定协作记忆：宪法、当前状态、决策记录、待验证清单、线程交接模板。
2. 再建立验收清单：把钱、短信、权限、结算、生产配置这些高风险项列清楚。
3. 最后做 Harness 第一阶段：后台安全验收台，只检查，不自动触发真实高风险动作。
